## 缓解快速滚动卡顿（BaseOptionsMenu）
用户反馈快速滚动（Shift / 触屏拖拽）时游戏卡。根因：`changeSelection` 每次都 `FlxG.sound.play('scrollMenu')` 且 `refreshCandidatePanel()` 重建候选行；快速滚动一帧内多次调用会瞬间叠加大量音效实例 + 频繁 new FlxText/tween，造成音频与 GC 卡顿；同时 `updateItemLayout` 恒用缓动，多格跳跃时列表滞后产生“橡皮筋”观感。
缓解（`source/options/BaseOptionsMenu.hx`）：
- 滚动提示音限频：`SCROLL_SND_INTERVAL=0.04` 秒（约 25 次/秒上限），用 `_lastScrollSndT` 记录 `FlxG.game.ticks/1000`；一帧内多次调用只播一次，避免音效实例堆积。
- `updateItemLayout` 中 `|offset|>=2` 的项直接吸附到目标位置（y/x 不缓动），焦点附近（offset 0/±1）仍平滑缓动，消除大幅跳跃的滞后感。
- 已 lint 通过。若仍卡，进一步可对 STRING 选项的 `refreshCandidatePanel` 做差量更新（复用候选行而非每帧 new），但当前未做。

## KeyViewerPosState 移动端虚拟按键修复
- 问题：KeyViewerPosState 在移动端缺少返回/重置虚拟按键（`addTouchPad('NONE','B_C')` + `addTouchPadCamera()` + 手动坐标重定位，在完整 MusicBeatState 下渲染层级/坐标脆弱；且原 update 只判 `controls.BACK`，B 键本身不触发退出）。
- 方案：改用 `android.FlxVirtualPad`。注意 `FlxActionMode` 枚举**没有** `B_C`，故以 `FlxDPadMode.NONE, FlxActionMode.NONE` 构造后手动 `createButton` 添加 B/C（沿用 virtualpad 图集的 b/c 帧，标准右下布局：-86*3 为 B，-128*3 为 C）。
- 改动（仅 `source/options/KeyViewerPosState.hx`）：移除 touchPad 调用；新增 `_virtualpad` 成员；`update()` 中 B 键 `justPressed` 触发退出保存、C 键触发重置；`overlapsVirtualPad` 改查 `_virtualpad.buttonB/buttonC`；其余桌面逻辑（BACK 键、R 键、延迟存盘）不变。
- 经验：`FlxVirtualPad` 直接 `add` 进 state 即可始终渲染在最上层，无需 `touchPadCam`，比 TouchPad 在完整 state 下更稳健。
