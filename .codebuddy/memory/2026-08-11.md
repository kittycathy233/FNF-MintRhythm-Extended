# 2026-08-11

## KathyEngine 与 Psych 0.6.3 脚本兼容性分析
- 当前项目（KathyEngine，基于新版 Psych 1.0 架构）把 0.6.3 的顶层引擎类（Note/PlayState/Conductor/Paths/ClientPrefs 等）拆进 objects./states./backend./substates./cutscenes. 子包。
- 0.6.3 模组靠 `addHaxeLibrary('Note')`、`getPropertyFromClass('PlayState', ...)`、`runHaxeCode` 裸写短名，在新版因 `Type.resolveClass('Note')` 返回 null 而失效。
- 已有的 `DeprecatedFunctions.hx` 只覆盖被改名函数，不覆盖类路径；HScript `preset()` 预置短名但不覆盖 Lua 且清单不完整。
- 提出零风险方案：新增 `source/psychlua/LegacyClassAlias.hx`（短名→新全路径 Map），在 HScript.hx 两处 `addHaxeLibrary` 与 ReflectionFunctions.hx 全部 `Type.resolveClass` 调用处改为「解析失败回退别名」，并把别名短名预注册为脚本全局变量。报告见 `research_report_psych_063_compat.md`。
- 局限：`Paths`/`Song`/`WeekData`/`Conductor` 内部 API 与数据结构在新架构下不同，需逐模组适配；`Section`、`Boyfriend` 已不存在（Boyfriend 并入 Character）。

## 实施 0.6.3/0.7.3 兼容补丁（已完成）
- 已落地 `source/psychlua/LegacyClassAlias.hx`：旧短名→当前全路径 Map（Note→objects.Note、PlayState→states.PlayState 等共 25 项），并对 Boyfriend/Section/ModManager/ColorblindFilter/Splash 等已移除/改名类加注释说明。
- 已改 `HScript.hx`：原生与 Lua 两处 `addHaxeLibrary` 在 `Type.resolveClass` 失败时回退 `LegacyClassAlias.resolve`；`preset()` 末尾遍历别名表预注册短名为脚本全局，使不调用 addHaxeLibrary 的旧写法也能跑。
- 已改 `ReflectionFunctions.hx`：`getPropertyFromClass`/`setPropertyFromClass`/`callMethodFromClass`/`createInstance`/`parseSingleInstance` 共 5 处 `Type.resolveClass` 统一改为 `LegacyClassAlias.resolve`。
- 针对截图中 `scarlet-spooky.lua` 的 `addHaxeLibrary('Boyfriend')` / `new Boyfriend(...)` 报错，追加 `Boyfriend => objects.Character` 别名做最佳努力兼容（旧 Boyfriend 已并入 Character，构造参数匹配）。

## 脚本函数级兼容性（setProperty 等）补丁
- 经三代码库（当前/0.6.3/0.7.3）抽取 `set(`/`add_callback` 注册点比对：
  - **属性族 setProperty/getProperty/*FromClass/*FromGroup 完全向后兼容**：当前仅末尾新增可选参数 `?allowMaps`/`?allowInstances`，且 getPropertyFromClass/setPropertyFromClass 内部已用 `LegacyClassAlias.resolve` 解析类名（更宽松）。用户最关心的 setProperty 等无需补丁。
  - **callMethod 族** 0.7.3 与当前一致；0.6.3 没有（不构成断裂）。
  - **精灵/补间/声音族** 全部向后兼容（可选参数化）。
- **已补回的缺失函数**（新建 `source/psychlua/LegacyScriptFunctions.hx`，`implement(funk)` 在 FunkinLua 构造函数中调用，与 DeprecatedFunctions 同模式，0 lint）：
  - `changePresence`（仅 0.6.3，当前改名 changeDiscordPresence；核实当前 changeDiscordPresence 实际绑定 DiscordClient.changePresence 散参函数，签名兼容，仅加别名）`#if DISCORD_ALLOWED`。
  - `getGlobalFromScript`/`setGlobalFromScript`（0.6.3/0.7.3 均有，当前彻底移除）：用 `game.luaArray` 定位目标脚本实例、读其 `lua` 状态写/读全局，匹配 `scriptName == luaFile || scriptName.endsWith(luaFile)`。
- **已知缺口（未自动补，需专项处理）**：
  - `runHaxeCode`/`addHaxeLibrary` 的 Lua 端消失（当前仅 HScript.implement 注册），0.6.3 .lua 模组常依赖；需 Lua→HScript 桥接，改动大，建议改独立 .hscript。
  - `doTweenZoom` 语义反转（旧第2参=对象名做zoom；当前第2参=相机名），自动判断代价高，建议模组侧改用 `startTween(tag, obj, {zoom=value}, dur, {ease=...})`。
  - `setHealth()`/`setAchievementScore()` 默认值变化（0→1 / 1→0），仅影响无参调用。
- 报告已加「脚本函数级兼容性」小节、补全结论与 References #9。

## 新增 legacyHUD 设置（旧版HUD布局兼容）
- 根因：KathyEngine 把内置 HUD 元素（timeBar/timeTxt/healthBar/iconP1/iconP2/scoreTxt/botplayTxt/replayTxt/watermarkText/ratingCounter）全部加入 `uiGroup`（FlxSpriteGroup）再挂到 camHUD；而 0.6.3 是 `add(...)` 直接进 PlayState.members，rating 也 `insert(members.indexOf(strumLineNotes), rating)` 直接进 members。旧版模组脚本用 `getObjectOrder('healthBar')`/`setObjectOrder` 把自定义 UI 排在内置 HUD 旁，依赖这些元素是 state 的直接成员；嵌套在 uiGroup 里会导致 `members.indexOf` 返回 -1 而失效。
- 改动：
  - `ClientPrefs.hx` 新增 `public var legacyHUD:Bool = false;`。
  - `ExtraGameplaySettingSubState.hx` 在 legacynotepos 后新增 BOOL 选项 `legacyHUD`，三语言（zh_cn/zh_tw/en_us）`options/*.json` 补 `legacy_hud` / `legacy_hud_desc`。
  - `PlayState.hx` 新增 `addToHUD(obj)`：legacyHUD 开启时 `add(obj); obj.cameras=[camHUD];`（直接进 state），否则 `uiGroup.add(obj)`。原 10 处 `uiGroup.add(...)` 全部替换为 `addToHUD(...)`；`ratingCounterModule.addToGroup(uiGroup)` 改为 legacy 时把 ratingTexts/maText/paText/sickPlusText 直接 add 进 state 并设 cameras=[camHUD]。
- 说明：初版仅扁平化 uiGroup。后续用户要求最完整复刻 0.6.x，扩展为 noteGroup + comboGroup 也扁平化。

## legacyHUD 扩展：noteGroup + comboGroup 扁平化（最完整复刻 0.6.x）
- 用户选择「noteGroup + comboGroup」最完整方案。核心目标：让 `getObjectOrder('strumLineNotes')`/`getObjectOrder('notes')` 及 0.6.x 式 `insert(members.indexOf(strumLineNotes), rating)` 在 KathyEngine 下可用。

  - `addToComboLayer(obj)`：legacyHUD 时**仍 comboGroup.add(obj) 作逻辑索引**（供 comboStacking/对象池定位），同时 `obj.cameras=[ratingsPos=='camHUD'?camHUD:camGame]` 并 `insert(members.indexOf(strumLineNotes), obj)`（复刻 0.6.x 直接进 members 渲染）；否则 `comboGroup.add(obj)`。替换 4 处 `comboGroup.add(...)`（theEXrating/rating/comboSpr/numScore）。
  - `removeComboSpr(spr)`：统一移除——非 legacy 仅 `comboGroup.remove`；legacy 额外 `members.remove`（因 comboGroup 不进 state 不渲染）。`killComboSprite` 与 cleanup 的 `comboGroup.remove` 均改用此函数。
- 组加入逻辑：920-922 原 `add(comboGroup)/add(uiGroup)/add(noteGroup)` 包进 `if(!legacyHUD)` 块；legacy 下三个组都不进 state，元素改由 addToHUD/addToNoteLayer/addToComboLayer 直接 add 进 state。
- countdown sprite：`insert(members.indexOf(noteGroup), spr)` 改为 legacy 时用 `members.indexOf(strumLineNotes)` 为参照（与 0.6.x 一致）。
- 保留：laneCovers 仍是 `add(laneCovers)` 直接进 members（0.6.x 本就如此，无需改）。
- 验证：所有 noteGroup.add/comboGroup.add/uiGroup.add 业务调用已替换；lint 0 错误。未实际编译运行（需 Android 构建环境），建议后续实机验证 legacy 模式渲染层级与 rating 回收。
